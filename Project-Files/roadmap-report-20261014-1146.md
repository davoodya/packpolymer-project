## فاز ۱ — زیرساخت، هاستینگ و آماده‌سازی وردپرس  —  ۰٪
> بستری سریع، امن و بومی‌شده که بتواند کاتالوگ فنی سنگین و ترافیک B2B را بدون افت سرعت تحمل کند.

**شرط اتمام فاز:** وردپرس نصب و فارسی/شمسی‌شده، SSL و امنیت پایه فعال، استیجینگ و بکاپ خودکار روزانه، SMTP تست‌شده.

### [ ] انتخاب و آماده‌سازی هاست/سرور  (≈ ۲ روز · فنی)
- [ ] ویرایش زیر مرحله
- [ ] سایزینگ شروع را انتخاب کن: حداقل ۲ vCPU، ۴GB RAM و دیسک NVMe (برای ۳ تا ۵ هزار محصول کافی است).
- [ ] استک سرور را تعیین کن: LiteSpeed یا Nginx، PHP نسخه ۸.۲ یا ۸.۳، MySQL 8 / MariaDB 10.6، OPcache و Redis.
- [ ] محل سرور را بر اساس بازار اصلی تعیین کن (سرور داخل ایران برای مشتری ایرانی، سرور خارج برای صادرات) و CDN مناسب را در نظر بگیر.
- [ ] محدودیت‌های واقعی میزبانی را بخوان: سهم CPU/RAM، تعداد inode/فایل، تعداد بازدید مجاز، سیاست ترافیک.
- [ ] پلن پشتیبان‌گیری هاست (Snapshot روزانه یا هفتگی) و امکان بازگردانی سریع را بررسی کن.
- [ ] فضای جداگانه برای ذخیره PDF، عکس و بکاپ در نظر بگیر تا با رشد کاتالوگ سرور کم نیاورد.

### [ ] نصب و تنظیم وردپرس پایه  (≈ ۱ روز · فنی)
- [ ] آخرین نسخه وردپرس را روی ریشه دامنه (Root) نصب کن، نه در زیرپوشه.
- [ ] دیتابیس اختصاصی با یوزر جدا بساز؛ پیشوند جدول را از wp_ به چیزی غیرقابل‌حدس تغییر بده.
- [ ] در wp-config.php تنظیم کن: DISABLE_FILE_EDIT، WP_MEMORY_LIMIT، WP_POST_REVISIONS محدود، WP_DEBUG فقط در محیط محلی.
- [ ] تنظیمات پایه را اعمال کن: عنوان‌بندی سایت، ساختار پیوند یکتا به شکل /product/%postname%/ و /category/%postname%/.
- [ ] پلاگین‌ها و قالب‌های پیش‌فرض بی‌استفاده را حذف کن (Hello Dolly، قالب‌های اضافه).
- [ ] کاربر مدیر با نام کاربری اختصاصی بساز و رمزهای قوی + نقش‌های درست تعریف کن.

### [ ] امنیت پایه و سخت‌سازی (Hardening)  (≈ ۲ روز · فنی)
- [ ] SSL را اجباری کن، HSTS را فعال کن و از http و نسخه بدون www به نسخه اصلی ریدایرکت کن.
- [ ] ورود دو مرحله‌ای (2FA) برای ادمین‌ها و محدودسازی تعداد تلاش ورود را فعال کن.
- [ ] XML-RPC را غیرفعال و REST API را محدود کن؛ آدرس ورود (login) را تغییر بده.
- [ ] فایروال اپلیکیشن (Wordfence/Cloudflare WAF) و مسدودسازی بدبات‌ها و اسکرپرهای قیمت را فعال کن.
- [ ] دسترسی فایل‌ها را درست تنظیم کن (644/755) و اجرای PHP در پوشه uploads را ببند.
- [ ] لاگ تغییرات کاربران و لاگ فعالیت ادمین را فعال کن تا بعداً قابل ردیابی باشد.

### [ ] محیط استیجینگ و ورک‌فلوی انتشار  (≈ ۱ روز · فنی)
- [ ] محیط استیجینگ بساز (WP Staging یا ابزار هاست) و آن را با داده‌های واقعی ولی انبوه تست کن.
- [ ] برای قالب و پلاگین‌های اختصاصی، مخزن Git راه بینداز و نسخه‌بندی کن.
- [ ] فایل‌های حساس (wp-config، توکن‌های درگاه) هرگز در مخزن قرار نگیرند؛ از متغیر محیطی استفاده کن.
- [ ] فرآیند انتشار را مستند کن: توسعه → استیج → تست (چک‌لیست) → انتشار زمان‌بندی‌شده در بازه کم‌ترافیک.

### [ ] بکاپ‌گیری و طرح بازیابی (Disaster Recovery)  (≈ ۱ روز · فنی)
- [ ] بکاپ خودکار روزانه دیتابیس + فایل‌ها با نگهداری حداقل ۳۰ نسخه راه بینداز (UpdraftPlus یا ابزار هاست).
- [ ] بکاپ را در فضای ذخیره‌سازی جداگانه نگه دار (S3، گوگل درایو، فضای ابری ایرانی) نه فقط روی همان سرور.
- [ ] یک بکاپ قبل از هر عملیات پرخطر (ایمپورت انبوه، آپدیت قالب، مهاجرت) دستی بگیر.
- [ ] هدف زمانی بازیابی (RTO) و میزان داده قابل از دست رفتن (RPO) را تعیین و مستند کن.
- [ ] تاریخچه بکاپ‌ها را ماهانه بازبینی کن و نسخه‌های خراب را پاک کن.

### [ ] فارسی‌سازی، تاریخ شمسی و تنظیمات محلی  (≈ ۱ روز · فنی/محتوا)
- [ ] زبان وردپرس را فارسی کن و RTL را در سطح قالب یکدست کن.
- [ ] تاریخ شمسی را فعال کن (افزونه تاریخ جلالی یا WP-Parsidate) و قالب نمایش تاریخ/زمان را تنظیم کن.
- [ ] منطقه زمانی Asia/Tehran، فرمت تاریخ و ساعت را تنظیم کن.
- [ ] واحد پول را تومان بگذار و اعداد فارسی/انگلیسی را در سراسر سایت یکدست کن.
- [ ] رشته‌های ترجمه‌نشده پلاگین‌ها را با Loco Translate فارسی کن.

### [ ] ایمیل تراکنشی و SMTP  (≈ ۱ روز · فنی)
- [ ] SMTP را تنظیم کن (Zoho/Microsoft 365/سرویس تراکنشی) و ارسال را با ایمیل واقعی تست کن.
- [ ] رکوردهای SPF، DKIM و DMARC دامنه را تنظیم کن تا ایمیل‌ها اسپم نشوند.
- [ ] قالب ایمیل فارسی و RTL بساز: ثبت سفارش، پیش‌فاکتور، تغییر وضعیت، یادآوری پرداخت، تأیید حساب B2B.
- [ ] پیوست PDF فاکتور را تست کن و اندازه آن را بهینه نگه دار.
- [ ] صف ایمیل را تست کن (۵۰ ایمیل پشت سر هم) تا سرعت هاست یا محدودیت سرویس ایمیل مشخص شود.

## فاز ۰ — استراتژی، بازار و برنامه کسب‌وکار  —  ۳۳٪
> قبل از هر خط کد، مدل درآمدی B2B + B2C، درخت محصولات، سیاست قیمت‌گذاری و KPI مشخص شود. خروجی این فاز «سند تصمیم» است، نه وب‌سایت.

**شرط اتمام فاز:** سند یک‌صفحه‌ای شامل ICP، درخت کاتالوگ، جدول قیمت‌گذاری، فهرست KPI و Roadmap تأییدشده.

### [ ] مطالعه بازار، رقبا و تعریف پرسونا (ICP)  (≈ ۴ روز · مارکتینگ)
- [ ] ۵ تا ۸ رقیب آنلاین (فروشگاه پلیمر، فروشگاه سیلیکون، بازارهای عمومی مثل دیجی‌کالا/باسلام) و رقبای آفلاین محلی را فهرست کن.
- [x] برای هر رقیب ثبت کن: نمایش یا عدم نمایش قیمت، سرعت سایت، کیفیت صفحه محصول، وجود TDS/MSDS، امکان استعلام قیمت آنلاین.
- [x] صنایع هدف B2B را لیست کن: بسته‌بندی، لوله و اتصالات، خودرو و قطعات، لوازم خانگی، سیم و کابل، ساختمانی، پزشکی، قالب‌سازی سیلیکون، رنگ و پوشش.
- [x] حداقل با ۸ مشتری واقعی (تلفنی یا حضوری) صحبت کن و دقیقاً ثبت کن چه واژه‌ای برای جست‌وجوی محصول به کار می‌برند (گرانول، گلوله، دانه، رزین، خامه، سیلیکون).
- [ ] برای هر پرسونا یک کارت بساز: نقش، دغدغه، معیار انتخاب، مانع خرید و اینکه سایت باید چه چیزی را فوراً به او نشان دهد.
- [ ] Value Proposition هر بخش را در یک جمله بنویس و آن را در Home و پیج دسته‌بندی استفاده کن.

### [x] طراحی مدل کسب‌وکار ترکیبی (B2B + B2C)  (≈ ۳ روز · مدیر محصول / بنیان‌گذار)
- [x] سهم هدف فروش را بین B2C (خرده: کیسه ۱ تا ۵ کیلویی، سیلیکون قالب‌گیری، چسب) و B2B (عمده: پالت، تنی، قرارداد فصلی) مشخص کن؛ مثلاً ۳۰٪ / ۷۰٪.
- [x] سه لایه مشتری را تعریف کن: مصرف‌کننده نهایی (B2C)، کارگاه و تولیدی کوچک (B2B خرد)، کارخانه و توزیع‌کننده استانی (B2B عمده).
- [x] برای هر لایه، حداقل سفارش (MOQ)، واحد فروش و زمان تحویل (Lead time) را جدا تعیین کن.
- [x] تصمیم بگیر فروش B2B آنلاین نهایی می‌شود یا با تأیید کارشناس؛ اگر دومی، مسیر «ثبت سفارش → تماس تأیید → لینک پرداخت» را طراحی کن.
- [x] جریان‌های درآمدی مکمل را بنویس: کرایه حمل، خدمات فنی/مشاوره گرید، برش و بسته‌بندی سفارشی، کمیسیون نمایندگی، فروش نمونه (Sample).
- [x] معیار موفقیت هر بخش را به‌صورت عددی بنویس (مثلاً: روزی ۱۵ سفارش B2C و هفته‌ای ۱۰ RFQ معتبر B2B در ماه ششم).

### [ ] استراتژی قیمت‌گذاری و سیاست تسویه  (≈ ۳ روز · مدیر مالی / فروش)
- [ ] مبنای قیمت را تعیین کن: نرخ پایه بورس کالا / فوب پتروشیمی + حاشیه سود، با قانون بازبینی روزانه یا هفتگی.
- [ ] جدول قیمت پله‌ای (Volume/Tiered Pricing) بساز: ۱–۲۵kg، ۲۶–۱۰۰kg، ۱۰۱–۵۰۰kg، ۵۰۱kg تا ۱ تن، بالای ۱ تن.
- [ ] گروه‌های کاربری و درصد تخفیف هر گروه را مشخص کن: B2C، عمده، نماینده استانی، کارخانه، پیمانکار.
- [ ] سقف تخفیف قابل اعمال خودکار در سایت و سطح تأیید انسانی را تعیین کن (مثلاً بالای ۷٪ نیاز به تأیید مدیر فروش).
- [ ] تصمیم بگیر قیمت B2B عمومی است، بعد از ورود نمایش داده می‌شود، یا فقط با «استعلام قیمت» اعلام می‌شود.
- [ ] سیاست مالیات (VAT ۱۰٪)، کرایه، بیمه، تخفیف پرداخت نقدی در برابر چک و شرایط تسویه (نقدی / ۳۰ / ۶۰ / ۹۰ روز) را روی کاغذ بیاور.
- [ ] سیاست نوسان ارز را بنویس: در نوسان شدید، اعتبار قیمت ۲۴ ساعته و سفارش‌های بالای یک آستانه نیازمند تأیید مجدد.

### [ ] درخت کاتالوگ و تاکسونومی محصولات (Product Taxonomy)  (≈ ۴ روز · کارشناس فنی محصول)
- [ ] شاخه پلیمر: ترموپلاستیک‌ها (PP, PE, PVC, PS, ABS, PET, PA, PC, PMMA, POM)، ترموست‌ها (اپوکسی، پلی‌استر، پلی‌یورتان، فنولیک)، الاستومرها (SBR, NBR, EPDM, SBS) و مستربچ/افزودنی.
- [ ] شاخه سیلیکون: LSR، HTV (HCR)، RTV-2، سیلیکون مایع (Silicone Fluid)، سیلیکون قالب‌گیری (Tin cure / Platinum cure)، گرید غذایی و پزشکی، چسب و درزگیر، آنتی‌فوم و دترجنت سیلیکونی.
- [ ] شاخه خدمات و ملزومات: قالب سیلیکونی، کاتالیزور و هاردنر، رنگدانه مخصوص سیلیکون، ابزار و تجهیزات تزریق.
- [ ] Attribute های فنی هر دسته را قطعی کن: Grade، MFI/MVR، Density، Hardness (Shore A)، Viscosity (cSt)، Catalyst ratio، Cure time، Color، Application.
- [ ] واحد و بسته‌بندی استاندارد را تعیین کن: کیلوگرم، تن، کیسه ۲۵kg، Big Bag ۱۰۰۰kg، بشکه ۲۰۰kg، سطل ۲۰kg، کارتن.
- [ ] قاعده نام‌گذاری محصول را بنویس: [برند] [نوع] [گرید] [مشخصه کلیدی] [بسته‌بندی] — مثال: «پلی‌پروپیلن جم ۵۵۲R گرید تزریقی — کیسه ۲۵ کیلوگرمی».

### [ ] انتخاب پلتفرم و معماری فنی  (≈ ۲ روز · فنی)
- [x] گزینه‌ها را مقایسه و مستند کن: WordPress + WooCommerce در برابر SaaS و پلتفرم اختصاصی (هزینه، مالکیت داده، انعطاف قیمت‌گذاری، سرعت توسعه).
- [x] نیازهای واقعی را عددی کن: تعداد SKU، بازدید ماهانه، کاربر همزمان، تعداد فایل فنی، نیاز به ERP.
- [x] تصمیم چندزبانه (fa/en) و چندارزی بگیر و اثر آن را روی ساختار URL از ابتدا لحاظ کن.
- [x] معماری منطقی را بکش: WP + WooCommerce + پلاگین B2B + لایه داده محصول (PIM-lite) + CRM + ایمیل/پیامک.
- [x] Roadmap فازبندی‌شده با MVP بنویس (چه چیزی در نسخه ۱ هست و چه چیزی به نسخه ۲ موکول می‌شود).
- [x] بودجه سالانه را برآورد کن: هاست، دامنه، لایسنس قالب و پلاگین‌ها، درگاه، پیامک، نگهداری و توسعه.

- [ ] WooCommerce را نصب کن و Setup Wizard را با دقت و بدون پذیرش پیش‌فرض‌ها طی کن.
- [ ] واحد وزن پایه را کیلوگرم (kg) و واحد ابعاد را سانتی‌متر بگذار.
- [ ] صفحه‌های فروشگاه، سبد، تسویه‌حساب و حساب کاربری را بساز و شورت‌کدها را در قالب بازبینی کن.
- [ ] کشور فروش و کشورهای مجاز ارسال را تعیین کن (ایران به‌علاوه بازارهای صادراتی).
- [ ] گزینه مهمان‌خرید (Guest Checkout) را روشن کن برای B2C و برای B2B نمایش قیمت را محدود کن.

### [ ] تنظیمات مالی، مالیات و واحد پول  (≈ ۱ روز · مالی/فنی)
- [ ] واحد پول را تومان، جایگاه نماد و تعداد اعشار (۰ رقم برای مبالغ بزرگ) تنظیم کن.
- [ ] مالیات را فعال کن و نرخ استاندارد (مثلاً VAT ۱۰٪) را تعریف کن؛ برای گروه B2B معافیت/وضعیت مالیاتی را جدا بنویس.
- [ ] نحوه نمایش قیمت را تعیین کن: شامل مالیات برای B2C و بدون مالیات برای مشتریان حقوقی.
- [ ] متن فاکتور، شماره‌گذاری و سریال فاکتور رسمی را استاندارد کن.
- [ ] کدهای تخفیف را ساختارمند بساز (درصدی برای عمده، مبلغ ثابت برای B2C) و تاریخ انقضا بگذار.

### [ ] حمل‌ونقل، لجستیک و محاسبه کرایه  (≈ ۳ روز · فنی/عملیات)
- [ ] مناطق ارسال را بساز: تهران (پیک)، شهرستان (تیپاکس/پست پیشتاز)، ارسال با باربری، تحویل درب انبار (EXW)، ارسال با ترابری مشتری.
- [ ] روش‌های کرایه را تعریف کن: کرایه ثابت، کرایه پله‌ای بر اساس وزن، کرایه رایگان با حداقل خرید، کرایه توافقی/پس‌کرایه.
- [ ] وزن هر محصول را دقیق وارد کن (وزن خالص + بسته‌بندی) تا محاسبه کرایه و پالت درست کار کند.
- [ ] هزینه‌های فرعی را تعریف کن: بسته‌بندی ویژه، پالت‌بندی، تخلیه، بیمه حمل، هزینه مناطق آزاد و عوارض.
- [ ] SLA ارسال را بنویس (زمان آماده‌سازی، ساعت برش سفارش) و در صفحه تسویه به مشتری نشان بده.
- [ ] رویه برخورد با آسیب حین حمل و پیگیری خسارت باربری را مستند کن.

### [ ] درگاه پرداخت و روش‌های تسویه  (≈ ۲ روز · فنی/مالی)
- [ ] درگاه پرداخت آنلاین (زرین‌پال/آی‌دی‌پی/به‌پرداخت) را نصب و با تراکنش واقعی کم‌مبلغ تست کن.
- [ ] روش‌های تسویه را به ترتیب فعال کن: پرداخت آنلاین، کارت به کارت با بارگذاری رسید، حواله/ساتنا، چک، تسویه اعتباری.
- [ ] برای پرداخت کارت به کارت، فیلد آپلود رسید و وضعیت «در انتظار تأیید» بساز.
- [ ] فرآیند خرید با فاکتور و مهلت پرداخت (Net 30/60) را با ادمین تعریف کن و به گروه‌های مجاز محدود کن.
- [ ] رویه بازگشت وجه، مغایرت پرداخت و لغو سفارش را در پنل و در قوانین سایت بنویس.
- [ ] تراکنش‌های مشکوک و تست‌های ناموفق را در گزارش روزانه درگاه پایش کن.

### [ ] حساب کاربری، ثبت‌نام و احراز هویت  (≈ ۲ روز · فنی)
- [ ] ورود و ثبت‌نام با شماره موبایل + کد یک‌بارمصرف را جایگزین رمز ساده کن.
- [ ] فیلدهای پروفایل را تعریف کن: نوع کسب‌وکار (حقیقی/حقوقی)، نام شرکت، کد اقتصادی، شماره ثبت، شهر، صنعت، پست الکترونیک مالی.
- [ ] فرم «درخواست حساب B2B» بساز با آپلود مدارک (روزنامه رسمی/کارت ملی/مجوز) و وضعیت «در انتظار تأیید».
- [ ] سطح دسترسی کاربران را تعریف کن و امکان غیرفعال‌سازی حساب‌های غیرفعال را بگذار.
- [ ] رضایت‌نامه حریم خصوصی و ذخیره‌سازی داده را در فرم ثبت‌نام بگنجان.
- [ ] پیامک خوش‌آمد، تأیید حساب و یادآوری تکمیل مدارک را تنظیم کن.

### [ ] واحدها، وزن و اندازه‌گیری  (≈ ۱ روز · فنی)
- [ ] فروش بر اساس وزن را فعال کن و واحد نمایش (کیلوگرم / تن) را در صفحه محصول واضح نشان بده.
- [ ] قاعده گرد کردن مقدار و قیمت را تعیین کن (مثلاً گرد کردن به ۰٫۵ کیلوگرم و مبلغ نهایی به هزار تومان).
- [ ] بسته‌بندی‌ها را مدل کن: Variation (کیسه ۲۵kg / بشکه ۲۰۰kg) یا محصول مستقل، بسته به ساختار قیمت‌گذاری.
- [ ] محاسبه وزن سبد و کرایه را با اعداد واقعی (پالت ۱ تنی، بشکه ۲۰۰ کیلویی) تست کن.
- [ ] تبدیل واحد را کنترل کن (kg ↔ ton) تا در B2B مقدار اشتباه ثبت نشود.

## فاز ۳ — قالب، رابط کاربری و تجربه خرید (UI/UX)  —  ۰٪
> ساختن تجربه‌ای که خریدار فنی بتواند در کمتر از ۳۰ ثانیه مشخصات، بسته‌بندی، MOQ و راه استعلام قیمت را پیدا کند.

**شرط اتمام فاز:** صفحه اصلی، دسته‌بندی، محصول و تسویه روی موبایل و دسکتاپ تست‌شده، سریع و کاملاً RTL باشد.

### [ ] انتخاب و آماده‌سازی قالب  (≈ ۲ روز · فنی/UI)
- [ ] گزینه‌های رایج را بررسی کن: Woodmart، Flatsome، Blocksy، Kadence، Astra — از نظر سرعت، پشتیبانی RTL و سازگاری با B2BKing/Wholesale Suite.
- [ ] قالب را روی Child Theme نصب کن و تغییرات را فقط در Child اعمال کن.
- [ ] توکن‌های طراحی قالب را با هویت برند هم‌راستا کن (رنگ، شعاع گوشه، سایه، فونت).
- [ ] صفحه‌بندی فروشگاه را تعیین کن: تعداد ستون، حالت گرید/لیست (برای اقلام فنی، لیست با جدول مشخصات بهتر است).
- [ ] قالب را روی استیج با ۲۰۰ محصول تست کن و زمان بارگذاری را اندازه بگیر.

### [ ] سیستم طراحی و تایپوگرافی فارسی  (≈ ۳ روز · UI)
- [ ] Design Token بساز: رنگ اصلی/تیره، فونت Vazirmatn، اندازه‌ها، فاصله‌ها، شعاع گوشه، سایه.
- [ ] تنظیمات تایپوگرافی فارسی: line-height مناسب، اندازه پایه ۱۵–۱۶px، اصلاح نیم‌فاصله و اعداد فارسی در متن‌ها.
- [ ] ترکیب لاتین/فارسی را چک کن: کلمات انگلیسی فنی نباید با فونت fallback مضاعف رندر شوند.
- [ ] کنتراست رنگ و دسترس‌پذیری (WCAG AA) را بررسی کن؛ دکمه‌های حیاتی مثل «استعلام قیمت» باید کاملاً واضح باشند.
- [ ] یک استایل‌گاید ساده بساز تا توسعه‌دهنده بعدی از آن پیروی کند.

### [ ] هدر، مگامنو و جست‌وجوی صنعتی  (≈ ۴ روز · فنی/UI)
- [ ] مگامنو بساز: پلیمرها و سیلیکون‌ها با زیرمنوی برند، گرید و کاربرد صنعتی.
- [ ] جست‌وجوی زنده (AJAX Live Search) با تحمل غلط تایپی و جست‌وجو روی فیلدهای سفارشی (Grade/برند/نام لاتین).
- [ ] نوار اعلان بالای سایت برای «نرخ روز»، «ارسال با باربری» یا کمپین عمده‌فروشی.
- [ ] دسترسی سریع همیشه در دید: سبد خرید، لیست خرید (Order List)، پنل حساب، پیگیری سفارش، تماس.
- [ ] CTA دوگانه در هدر: «خرید خرد» برای B2C و «استعلام/پنل عمده» برای B2B.
- [ ] فوتر اعتمادساز: اینماد، تلفن ثابت، آدرس، ساعات کاری، لینک اسناد فنی و کاتالوگ.

### [ ] صفحه محصول حرفه‌ای (PDP) برای پلیمر و سیلیکون  (≈ ۵ روز · فنی/محتوا)
- [ ] جدول مشخصات فنی را به‌صورت ساختارمند نشان بده: Grade، MFI، Density، Hardness، Viscosity، Catalyst ratio، بسته‌بندی.
- [ ] دکمه‌های اصلی محصول: افزودن به سبد، افزودن به لیست خرید، استعلام قیمت، درخواست نمونه، دانلود TDS/MSDS/COA.
- [ ] نمایش MOQ، زمان آماده‌سازی/تحویل، وضعیت موجودی یا «تماس بگیرید» در بالای صفحه.
- [ ] جدول قیمت پله‌ای (Volume Pricing Table) و نمایش قیمت ویژه هر گروه کاربری.
- [ ] بخش محصولات جایگزین/مرتبط (Alternative Grades) برای زمانی که گرید مورد نظر موجود نیست.
- [ ] تب‌های محتوایی: توضیحات فنی، کاربردها، شرایط نگهداری، نکات ایمنی، پرسش‌های متداول.
- [ ] بلوک «کارشناس این محصول» با نام، شماره تماس/واتساپ و زمان پاسخ‌دهی.

### [ ] صفحه دسته‌بندی، فیلتر پیشرفته و مقایسه  (≈ ۴ روز · فنی)
- [ ] فیلترها را تعریف کن: برند، گرید، کاربرد صنعتی، رنگ، بسته‌بندی، موجودی، محدوده قیمت هر کیلو.
- [ ] حالت نمایش لیست با ستون‌های فنی را فعال کن (برای مقایسه سریع چند گرید کنار هم).
- [ ] مقایسه محصولات (Compare) و افزودن گروهی به سبد (Bulk Add to Cart) را فعال کن.
- [ ] قابلیت مرتب‌سازی حرفه‌ای: قیمت هر کیلو، پرطرفدار، جدیدترین، موجودی.
- [ ] URL فیلترها را ساختارمند کن و صفحه‌بندی/search را برای موتور جست‌وجو مدیریت کن.
- [ ] صفحه دسته را با متن فنی، تصویر، راهنمای انتخاب و CTA استعلام کامل کن.

### [ ] موبایل، سرعت و دسترس‌پذیری  (≈ ۳ روز · فنی)
- [ ] Core Web Vitals را روی موبایل واقعی بسنج: LCP، INP، CLS و رفع گلوگاه‌های اصلی.
- [ ] تصاویر را به WebP/AVIF تبدیل کن، ابعاد درست بده و Lazy Load را فعال کن.
- [ ] اسکریپت‌های اضافی قالب را حذف، تعویق (defer) و ادغام کن.
- [ ] دکمه چسبان «افزودن به سبد / استعلام» در موبایل و ساده‌کردن فرم تسویه‌حساب.
- [ ] تست رندر فارسی روی اندروید، iOS و ویندوز و اصلاح فاصله‌ها و برش متون.

## فاز ۴ — پلاگین‌ها و قابلیت‌های اختصاصی B2B  —  ۰٪
> تبدیل فروشگاه ساده به یک پلتفرم B2B واقعی: قیمت پله‌ای، MOQ، استعلام قیمت، اعتبار، سفارش سریع و حساب شرکتی.

**شرط اتمام فاز:** یک مشتری حقوقی بتواند ثبت‌نام کند، تأیید شود، قیمت اختصاصی ببیند، لیست خرید بفرستد، استعلام بگیرد و با اعتبار خرید کند.

### [ ] انتخاب و نصب پلاگین هسته B2B  (≈ ۲ روز · فنی/فروش)
- [ ] گزینه‌ها را بررسی کن: B2BKing، Wholesale Suite (Wholesale Prices + Order Form + Roles)، YITH B2B، افزونه‌های بومی فارسی.
- [ ] معیار انتخاب: قیمت نقش‌محور، MOQ، تأیید ثبت‌نام، RFQ، سازگاری RTL، پشتیبانی فعال، کیفیت مستندات.
- [ ] پلاگین را روی استیج نصب و سناریوهای واقعی را تست کن (تأیید کاربر، قیمت اختصاصی، MOQ).
- [ ] محدودیت‌ها و رفتار پلاگین با کش را مستند کن تا در تنظیمات سرعت لحاظ شود.
- [ ] پلن تهیه لایسنس و تمدید سالانه را مشخص کن.

### [ ] گروه‌های مشتری و قیمت‌گذاری پله‌ای  (≈ ۴ روز · فروش/فنی)
- [ ] گروه‌های مشتری را بساز: B2C، عمده، نماینده استانی، کارخانه، پیمانکار، صادراتی.
- [ ] برای هر گروه سطح دسترسی تعیین کن: نمایش قیمت، دیدن موجودی، مجوز خرید اعتباری، دیدن لیست قیمت.
- [ ] جدول قیمت پله‌ای بر اساس مقدار بساز (۱–۲۵، ۲۶–۱۰۰، ۱۰۱–۵۰۰، ۵۰۱–۱۰۰۰، ۱۰۰۰+ کیلوگرم).
- [ ] قیمت اختصاصی مشتری (Customer Specific Price) و لیست قیمت اختصاصی (Price List) را پیاده کن.
- [ ] حالت «مخفی‌سازی قیمت» برای کاربران مهمان با متن جایگزین مثل «برای مشاهده قیمت وارد شوید یا استعلام بگیرید».
- [ ] ابزار بروزرسانی گروهی قیمت‌ها (بر اساس درصد یا فایل اکسل) را آماده کن.
- [ ] تاریخ اعتبار قیمت (Price Validity) را نمایش بده تا مشتری بداند نرخ چند روز اعتبار دارد.

### [ ] استعلام قیمت (RFQ) و پیش‌فاکتور  (≈ ۵ روز · فنی/فروش)
- [ ] فرم استعلام قیمت بساز: محصول، مقدار (kg/تن)، بسته‌بندی، شهر تحویل + امکان آپلود لیست خرید (Excel/عکس).
- [ ] RFQ را در پنل مدیریت ذخیره کن و به کارشناس مربوطه اطلاع بده (ایمیل + پیامک + پنل).
- [ ] وضعیت‌های پیگیری را تعریف کن: جدید، در حال بررسی، قیمت ارسال شد، تبدیل به سفارش، بسته‌شده.
- [ ] تولید پیش‌فاکتور PDF فارسی با سربرگ، شرایط فروش، مهلت اعتبار و مهر/امضا.
- [ ] امکان تبدیل استعلام به سفارش با یک کلیک و ارسال لینک پرداخت اختصاصی به مشتری.
- [ ] گزارش هفتگی نرخ تبدیل RFQ به سفارش و دلایل بسته‌نشدن را استخراج کن.

### [ ] MOQ، خرید اعتباری و شرایط تسویه B2B  (≈ ۴ روز · فروش/مالی)
- [ ] حداقل سفارش (MOQ) را در سطح محصول، دسته یا کل سبد تعریف و اعمال کن.
- [ ] قواعد مخلوط‌کردن اقلام در MOQ را مشخص کن (مثلاً حداقل ۲۵ کیلو از هر قلم و ۱۰۰ کیلو در کل سبد).
- [ ] پنل اعتبار مشتری بساز: سقف اعتبار، مانده بدهی، صورتحساب، تاریخ سررسید.
- [ ] گزارش سنی بدهی (Aging Report) و یادآوری خودکار سررسید را فعال کن.
- [ ] قاعده توقف سفارش در صورت بدهی معوق را با هشدار و مسیر تسویه پیاده کن.
- [ ] شرایط تخفیف پرداخت نقدی در برابر چک و ضمانت‌نامه را در فاکتور لحاظ کن.

### [ ] ابزارهای خریدار حرفه‌ای (Quick Order و Reorder)  (≈ ۴ روز · فنی)
- [ ] فرم سفارش سریع (Quick Order Form) با جست‌وجوی SKU/نام و افزودن چند قلم در یک صفحه.
- [ ] آپلود فایل اکسل/CSV لیست خرید و تبدیل خودکار به سبد (با گزارش اقلام ناموفق).
- [ ] سفارش مجدد از تاریخچه سفارش‌ها با یک کلیک و امکان ویرایش مقادیر.
- [ ] لیست خرید (Requisition List) با قابلیت چاپ، اشتراک‌گذاری لینک و تبدیل به سفارش.
- [ ] لیست علاقه‌مندی و هشدار موجودی/نرخ برای اقلام پرتکرار.
- [ ] گزارش «پرفروش‌ترین اقلام هر مشتری» برای پیشنهاد فروش کارشناس.

### [ ] حساب کاربری شرکتی و سطوح دسترسی  (≈ ۴ روز · فنی)
- [ ] ساختار سازمانی بساز: یک حساب شرکت با چند کاربر (خریدار، مدیر خرید، حسابدار، انبار).
- [ ] نقش‌ها را تعریف کن: ثبت سفارش، تأیید سفارش، مشاهده فاکتور، مدیریت کاربران سازمان.
- [ ] فیلدهای سازمانی و آپلود مدارک (روزنامه رسمی، کد اقتصادی، کارت ملی مدیر) را اضافه کن.
- [ ] دسترسی هر کاربر به تاریخچه سفارش‌ها، فاکتورها و خروجی اکسل را کنترل کن.
- [ ] گزارش خرید سازمانی (Purchase History) برای تطبیق با حسابداری فراهم کن.
- [ ] قابلیت انتقال کارمندان بین شرکت‌ها و غیرفعال‌سازی کاربران را در نظر بگیر.

### [ ] اتصال به ERP/انبار و قیمت لحظه‌ای  (≈ ۱ هفته · فنی/انبار)
- [ ] روش اتصال را انتخاب کن: پلاگین واسط آماده، API اختصاصی یا سرویس میانی (Middleware).
- [ ] همگام‌سازی موجودی و قیمت را زمان‌بندی کن (چند بار در روز یا پس از هر ورود فاکتور به انبار).
- [ ] SKU سایت را با کد کالای انبار/حسابداری یکسان کن و جدول نگاشت (Mapping) بساز.
- [ ] سناریوی «ناموجود شدن بین سفارش و ارسال» را مدیریت کن: اطلاع فوری + پیشنهاد جایگزین + بازگشت وجه.
- [ ] لاگ همگام‌سازی و هشدار خطا راه بینداز (اگر API قطع شد، سریع بفهمی).
- [ ] اگر اتصال ERP هنوز آماده نیست، مسیر موقت «بروزرسانی فایل اکسل روزانه» را با ابزار ایمپورت پیاده کن.

### [ ] چندزبانه و چندارزی برای فروش صادراتی  (≈ ۱ هفته · فنی/بازرگانی)
- [ ] افزونه چندزبانه (WPML/Polylang) را نصب کن و ساختار fa (RTL) و en (LTR) را درست پیاده کن.
- [ ] قیمت‌گذاری بر اساس ارز (دلار/یورو) و به‌روزرسانی نرخ ارز را تعریف کن.
- [ ] شرایط فروش صادراتی را شفاف کن: EXW، FOB، CIF و روش پرداخت (پیش‌پرداخت، LC).
- [ ] اسناد انگلیسی محصول (TDS/MSDS/COA) را آماده و به نسخه فارسی لینک کن.
- [ ] سئوی چندزبانه: hreflang، URL مجزا، محتوای ترجمه‌شده (نه ترجمه ماشینی خام).
- [ ] بخش «Export Inquiry» جداگانه با فرم و کارشناس اختصاصی بساز.

## فاز ۵ — داده محصول، محتوا و سئوی صنعتی  —  ۰٪
> ورود دقیق و انبوه کاتالوگ فنی (SKU، مشخصات، اسناد، تصاویر) و ساخت پایه‌ای برای رتبه گرفتن در جست‌وجوهای صنعتی.

**شرط اتمام فاز:** همه محصولات فعال با مشخصات کامل، اسناد فنی، تصویر و متای سئو؛ نرخ خطای داده نزدیک به صفر.

### [ ] طراحی ساختار داده و اسکیمای محصول  (≈ ۳ روز · فنی/محتوا)
- [ ] Attribute های سراسری را بساز: Brand، Grade، MFI، Density، Hardness، Viscosity، Color، Application، Packaging، Origin.
- [ ] تاکسونومی برند، گرید و کاربرد صنعتی را مستقل از دسته‌بندی محصول تعریف کن.
- [ ] ساختار Variation را برای بسته‌بندی (کیسه/بشکه/پالت) مشخص کن.
- [ ] قاعده SKU را پیاده کن، مثل: PP-JAM-552R-25KG (نوع-برند-گرید-بسته‌بندی).
- [ ] فیلدهای سفارشی را اضافه کن: فایل TDS، فایل MSDS، COA، کشور سازنده، شرایط نگهداری، تعرفه گمرکی.
- [ ] واحد اندازه‌گیری و وزن هر Variation را دقیق و یکدست وارد کن.

### [ ] آماده‌سازی و ورود انبوه محصولات (Import)  (≈ ۱ هفته · محتوا/فنی)
- [ ] قالب CSV/Excel استاندارد بساز: ستون‌های اجباری (نام، SKU، دسته، قیمت، واحد، وزن) و ستون‌های فنی.
- [ ] نام‌گذاری ستون‌ها را با فیلدهای ووکامرس تطبیق بده (Regular Price, Sale Price, Categories, Images, Attributes).
- [ ] با ۲۰ SKU تست ایمپورت کن و خطاهای انکودینگ (UTF-8)، جداکننده و دسته‌بندی را رفع کن.
- [ ] ابزار ایمپورت را انتخاب کن: WP All Import (+افزونه ووکامرس) یا ابزار داخلی ووکامرس برای حجم کم.
- [ ] محصولات را دسته‌به‌دسته و مرحله‌ای وارد کن و بعد از هر مرحله گزارش خطا بگیر.
- [ ] بازبینی نهایی هر SKU: دسته، قیمت، وزن، موجودی، تصویر، جدول مشخصات و متای سئو.
- [ ] یک شیت «لاگ ایمپورت» نگه دار تا اگر ردیفی رد شد، دوباره کاری نشود.

### [ ] تصاویر، اسناد فنی و مدیای محصول  (≈ ۴ روز · محتوا/فنی)
- [ ] استایل عکس محصول را تعریف و مستند کن (ابعاد، پس‌زمینه، زاویه، فرمت).
- [ ] عکس‌ها را فشرده و با نام فایل سئوپسند ذخیره کن: pp-jam-552r-25kg.webp.
- [ ] فایل‌های PDF (TDS/MSDS/COA) را با نام‌گذاری استاندارد آپلود و به محصول/دسته لینک کن.
- [ ] ویدیوهای کوتاه کاربردی بساز: تزریق، قالب‌گیری، ترکیب و تست سختی (Shore A).
- [ ] گالری، ۳۶۰ درجه یا تصویر بسته‌بندی انبار را اضافه کن (برای اعتماد B2B بسیار مؤثر).
- [ ] آلت تصاویر و متن جایگزین (Alt) را برای همه تصاویر بنویس.

### [ ] محتوای صفحات کلیدی و اعتمادسازی  (≈ ۱ هفته · محتوا)
- [ ] صفحات ثابت را بنویس: درباره ما، شرایط فروش، حمل و پرداخت، ضمانت اصالت کالا، پرسش‌های متداول، تماس.
- [ ] صفحه‌های لندینگ دسته‌بندی با متن فنی، جدول مقایسه گریدها و CTA استعلام بساز.
- [ ] خانه را با ساختار دوگانه بساز: ویترین B2C + بلوک «خرید عمده و همکاری با کارخانه‌ها».
- [ ] راهنماهای انتخاب محصول بنویس: «کدام گرید PP برای تزریق مناسب است؟»، «تفاوت سیلیکون قالب‌گیری قلعی و پلاتینی».
- [ ] نظرات و رضایت مشتریان صنعتی، لوگوی مشتریان و نمونه پروژه‌ها را (با اجازه) منتشر کن.
- [ ] صفحه «فروش عمده/نمایندگی» با شرایط همکاری و فرم درخواست بساز.

### [ ] سئوی تکنیکال و محتوایی صنعتی  (≈ ۲ هفته (پیوسته) · مارکتینگ)
- [ ] افزونه سئو (Rank Math/Yoast) را نصب و Sitemap، Schema (Product/Offer/Breadcrumb/FAQ) را تنظیم کن.
- [ ] تحقیق کلمات کلیدی صنعتی: «خرید پی‌وی‌سی»، «قیمت سیلیکون قالب‌گیری»، «گلوله پلی‌اتیلن»، «مستربچ کربنات» و ترکیب با نام برند/گرید.
- [ ] الگوی تایتل و متادیسکریپشن را برای محصول و دسته استانداردسازی کن (مرور روی ۲۰٪ اول محصولات).
- [ ] ساختار محتوایی ستون/خوشه (Pillar & Cluster) بساز و لینک داخلی بین بلاگ، دسته و محصول برقرار کن.
- [ ] صفحات فیلتر و برچسب کمارزش را noindex و محتوای تکراری را یکپارچه کن.
- [ ] سایت را در Google Search Console و Bing ثبت کن و هفتگی خطاهای پوشش (Coverage) را بررسی کن.

## فاز ۶ — تست، تضمین کیفیت و آماده‌سازی انتشار  —  ۰٪
> اطمینان از درست کار کردن پول، داده و انبار: پرداخت، مالیات، کرایه، ایمیل، گزارش‌ها و امنیت.

**شرط اتمام فاز:** چک‌لیست QA کامل بدون ایراد بحرانی؛ سفارش واقعی آزمایشی از ثبت تا تسویه و ارسال انجام‌شده باشد.

### [ ] تست عملیاتی سفارش (B2C و B2B)  (≈ ۳ روز · QA/عملیات)
- [ ] سفارش B2C با یک قلم و با چند قلم، با تخفیف، با ارسال پیک و با ارسال تیپاکس.
- [ ] سفارش B2B با قیمت اختصاصی، با MOQ، با پرداخت اعتباری و با چک.
- [ ] سفارش مهمان، سفارش با موبایل، سفارش چندمرحله‌ای نیمه‌کاره‌رها و ادامه خرید.
- [ ] لغو سفارش، بازگشت کالا، استرداد وجه و محاسبه مالیات اصلاحی برای سفارش تغییرکرده.
- [ ] سفارش با آپلود فایل سفارش سریع و سفارش مجدد از تاریخچه.

### [ ] تست تیم فروش و انبار  (≈ ۲ روز · عملیات)
- [ ] تست کامل چرخه انبار: دریافت سفارش، برداشت (Picking)، بسته‌بندی، تحویل به باربری، تغییر وضعیت در سایت.
- [ ] بررسی چاپ فاکتور، لیست برداشت، برچسب بسته‌بندی و بارنامه.
- [ ] آموزش پرسنل بسته‌بندی و فروش و نوشتن راهنمای یک‌صفحه‌ای برای هر نقش.
- [ ] تست چاپ رسید و فاکتور رسمی و تطابق شماره سریال با سیستم مالی.
- [ ] تست سناریوی موجودی ناکافی در آخرین لحظه و مسیر اطلاع‌رسانی به مشتری.

### [ ] تست امنیت، نفوذ و پایش  (≈ ۳ روز · فنی)
- [ ] تست دسترسی: کاربر مهمان، کاربر تأییدنشده، کاربر تأییدشده و ادمین — هر کدام چه چیزی را می‌بینند.
- [ ] تست برگهدان (QA) امنیت با پلاگین‌های امنیتی و بررسی لاگ تغییر فایل‌ها.
- [ ] داشبورد امنیتی را روزانه بررسی و فعالیت‌های مشکوک (تلاش ورود ناموفق، تغییر فایل، ساخت کاربر جدید) را ثبت کن.
- [ ] تست کپچا روی ورود/استعلام و بررسی رفتار پلاگین‌های ضدکلاهبرداری در برابر اسپم استعلام.
- [ ] بازبینی سطح دسترسی نقش‌های وردپرس و حذف دسترسی‌های اضافه کاربران.
- [ ] رفع هشدارها و مستندسازی موارد باقی‌مانده با مسئول و زمان‌بندی.

### [ ] تست سازگاری، مرورگر و دستگاه  (≈ ۲ روز · QA)
- [ ] تست کروم، فایرفاکس، سافاری، اج و کروم اندروید/iOS.
- [ ] تست روی نمایشگرهای ۱۳۶۶، ۱۴۴۰ و ۱۹۲۰ و مانیتورهای شرکتی قدیمی.
- [ ] تست فرم‌ها با کیبورد، Tab و دسترس‌پذیری پایه.
- [ ] تست کندی اینترنت (3G) و افت بارگذاری اسناد PDF.
- [ ] تست چاپ صفحات کلیدی (فاکتور، صفحه محصول، شرایط فروش).

### [ ] تست داده و گزارش‌های مالی  (≈ ۲ روز · مالی/QA)
- [ ] کنترل صحت SKU، قیمت، موجودی و وزن برای نمونه‌ای از محصولات (حداقل ۱۰٪).
- [ ] تست قالب ایمپورت برای افزودن محصولات آینده با ۱۰ ردیف جدید.
- [ ] تطبیق گزارش‌های فروش سایت با حسابداری (فروش، تخفیف، مالیات، کرایه).
- [ ] بررسی تاریخ شمسی، اعداد فارسی و واحد پول در فاکتور و ایمیل.
- [ ] تست بازیابی: بر اساس بکاپ، سایت و داده را روی استیج بازگردان و نتیجه را ثبت کن.

## فاز ۷ — کارایی، سرعت، کش و پایداری  —  ۰٪
> سایت با کاتالوگ سنگین و پرس‌وجوهای فیلتری، سریع و پایدار باقی بماند (به‌ویژه برای موبایل و صفحات دسته‌بندی).

**شرط اتمام فاز:** امتیاز PageSpeed بالای ۸۰ در موبایل، TTFB زیر ۵۰۰ms، بدون خطای ۵۰۲ در ساعات اوج.

### [ ] کش‌گذاری و بهینه‌سازی پایگاه داده  (≈ ۳ روز · فنی)
- [ ] کش صفحه (LiteSpeed Cache / WP Rocket / FlyingPress) را فعال کن و صفحات سبد/تسویه/حساب را از کش مستثنا کن.
- [ ] Redis Object Cache را برای کاهش کوئری دیتابیس فعال کن و تأثیر آن را عددی اندازه بگیر.
- [ ] جدول‌های اضافی (postmeta معیوب، revision، transients منقضی، جدول‌های پلاگین حذف‌شده) را پاک‌سازی کن.
- [ ] کوئری‌های سنگین و پلاگین‌های پرمصرف را با Query Monitor پیدا و جایگزین کن.
- [ ] زمان‌بندی بهینه‌سازی دیتابیس ماهانه را در تقویم نگهداری بگذار.

### [ ] CDN، فشرده‌سازی و دارایی‌ها  (≈ ۲ روز · فنی)
- [ ] فشرده‌سازی Gzip/Brotli و HTTP/2 یا HTTP/3 را فعال کن.
- [ ] CSS/JS را مینیفای و ادغام کن و بارگذاری اسکریپت‌های غیرضروری را به تعویق بینداز.
- [ ] فونت را میزبانی محلی کن و preload بگذار؛ از سرویس‌های فونت خارجی که ممکن است مسدود شوند پرهیز کن.
- [ ] راهبرد کش مرورگر (Cache-Control) برای تصاویر، فونت و PDF را تنظیم کن.
- [ ] مانیتورینگ آپ‌تایم (UptimeRobot یا سرویس داخلی) با هشدار پیامکی راه‌اندازی کن.

### [ ] پایداری در ترافیک اوج و کمپین  (≈ ۲ روز · فنی)
- [ ] تست بار با ۲۰۰ کاربر همزمان (Load Test) روی صفحات دسته‌بندی و محصول انجام بده.
- [ ] برای کمپین‌ها Fanout/کش را گرم کن و لینک صفحات پرترافیک را از قبل pre-warm کن.
- [ ] محدودیت ترافیک هاست و آستانه هشدار را مستند کن.
- [ ] صفحه تعمیرات (Maintenance) آماده و قابل فعال‌سازی سریع بساز.
- [ ] روی صفحات پرترافیک، درخواست‌های اضافی (آمارهای سنگین، اسکریپت‌های تبلیغاتی) را حذف کن.

## فاز ۸ — مارکتینگ، CRM و فروش (B2B + B2C)  —  ۰٪
> سایت را از یک کاتالوگ به یک ماشین تولید سرنخ و فروش تبدیل کن: کمپین، ایمیل/پیامک، CRM و پیگیری استعلام‌ها.

**شرط اتمام فاز:** حداقل دو کانال جذب فعال، یک قالب پیام برند، و پیگیری مستند استعلام‌ها در CRM.

### [ ] راه‌اندازی CRM و فرآیند پیگیری  (≈ ۱ هفته · فروش)
- [ ] CRM را انتخاب و متصل کن (نوآوران، پیام‌گستر، حلما، یا حتی یک CRM سبک خارجی).
- [ ] فرم‌ها را به CRM وصل کن: خبرنامه، استعلام قیمت، درخواست نمونه، فرم همکاری.
- [ ] مراحل قیف را تعریف کن: لید جدید → تماس اول → ارسال قیمت → نمونه/پیش‌فاکتور → سفارش → پیگیری پس از فروش.
- [ ] SLA پاسخ‌دهی را بنویس (مثلاً پاسخ حداکثر ۲ ساعت کاری) و رعایت آن را اندازه بگیر.
- [ ] منبع هر لید (UTM) را ثبت کن تا بفهمی کدام کانال بازده واقعی دارد.
- [ ] قالب تماس B2B بساز: سؤالات واجب (مقدار ماهانه، صنعت، زمان لازم، تصمیم‌گیرنده).

### [ ] ایمیل مارکتینگ، پیامک و اتوماسیون  (≈ ۱ هفته · مارکتینگ)
- [ ] خبرنامه B2C و B2B جدا راه بینداز و قالب ایمیل فارسی RTL بساز.
- [ ] اتوماسیون سبد رهاشده (۳ مرحله: ۱ ساعت، ۲۴ ساعت، ۷۲ ساعت با پیشنهاد جایگزین).
- [ ] پیامک مناسبت‌ها، تأیید سفارش، ارسال، یادآوری پرداخت و هشدار کاهش موجودی.
- [ ] لیست قیمت ماهانه/هفتگی برای مشتریان تأییدشده B2B ارسال کن.
- [ ] کمپین بازگشت مشتری خاموش (۳۰/۶۰/۹۰ روز) با پیشنهاد اختصاصی.
- [ ] سنجش نرخ باز شدن/کلیک و تنظیم محتوای پیام‌ها بر اساس داده.

### [ ] جذب ترافیک: محتوا، ظرفیت صنعتی و تبلیغات  (پیوسته · مارکتینگ)
- [ ] صفحه «نرخ روز پلیمر و سیلیکون» با تاریخ بروزرسانی و CTA استعلام بساز.
- [ ] مسیرهای محتوایی: آموزش فنی، مقایسه گریدها، انتخاب مواد، رفع عیب تزریق و قالب‌گیری.
- [ ] برای جست‌وجوی صوتی و هوش مصنوعی، صفحات پرسش‌ومحور (FAQ Schema) تولید کن.
- [ ] تبلیغات: گوگل ادز (Search صنعتی) + بنر تخصصی در سایت‌های پلیمری + شبکه‌های اجتماعی صنعتی.
- [ ] پیامدسازی (Retargeting) برای بازدیدکنندگان سبد و صفحات محصول.
- [ ] رصد جایگاه کلمات کلیدی و بودجه تبلیغات ماهانه با بازده (ROAS).

### [ ] فروش B2B: توسعه نمایندگی و مشتری کلیدی  (پیوسته · فروش)
- [ ] لیست ۱۰۰ مشتری هدف را بساز (کارخانه، توزیع‌کننده، پیمانکار) با اطلاعات تماس و نیاز سالانه.
- [ ] برنامه تماس دوره‌ای (هر ۲ هفته/ماه) و ثبت تعامل در CRM.
- [ ] بسته همکاری نمایندگی: قیمت نمایندگی، حداقل خرید فصلی، قلمرو فروش، آموزش و پشتیبانی.
- [ ] صلاحیت‌سنجی مشتری عمده (اعتبار، سابقه، توان پرداخت) قبل از اعطای خرید اعتباری.
- [ ] حضور در نمایشگاه‌ها/همایش‌های صنعت پلیمر و ساخت لندینگ اختصاصی رویداد.
- [ ] گزارش ماهانه عملکرد فروش B2B: تن فروش، مبلغ، حاشیه سود و مشتریان جدید.

### [ ] رشد B2C و بهینه‌سازی نرخ تبدیل  (پیوسته · مارکتینگ)
- [ ] بهینه‌سازی صفحه محصول B2C: سؤال‌های متداول، راهنمای مصرف، تصویر واقعی، نظر مشتریان.
- [ ] کار روی کاهش رهاسازی سبد: فرم کوتاه، نمایش هزینه ارسال زودتر، روش‌های پرداخت متنوع.
- [ ] باندل‌های فروش (کیت کامل قالب‌گیری سیلیکون: سیلیکون + هاردنر + رنگ + ابزار).
- [ ] برنامه وفاداری و تخفیف خرید دوم برای مشتریان تکراری.
- [ ] تست A/B روی عنوان، CTA و ترتیب محتوا در صفحات پرمخاطب.

## فاز ۹ — راه‌اندازی (Go-Live) و پس از راه‌اندازی  —  ۰٪
> انتشار کنترل‌شده سایت، انتقال بدون افت سئو، آموزش تیم و شروع چرخه نگهداری و بهبود.

**شرط اتمام فاز:** سایت منتشر شده، ایندکس‌شده، تیم آموزش‌دیده و برنامه نگهداری ماهانه فعال باشد.

### [ ] چک‌لیست پیش از انتشار  (≈ ۱ روز · PM/فنی)
- [ ] حذف حالت توسعه: noindex برداشته شده، robots.txt آزاد، WP_DEBUG خاموش، پیام‌های تست پاک.
- [ ] کنترل نهایی: قیمت‌ها، موجودی، اطلاعات تماس، حساب‌های بانکی، آدرس و نقشه.
- [ ] تست درگاه پرداخت با تراکنش واقعی کم‌مبلغ و بازگشت وجه آن.
- [ ] ریدایرکت‌های ۳۰۱ از دامنه/لینک‌های قدیمی به لینک‌های جدید.
- [ ] تاریخ‌گذاری زمان انتشار در بازه کم‌ترافیک و اطلاع دادن به کارشناسان فروش.
- [ ] فریز تغییرات (Change Freeze) چند روز قبل از انتشار و بکاپ کامل نهایی.

### [ ] فروش آزمایشی بسته (Soft Launch)  (≈ ۱ هفته · PM/فروش)
- [ ] دسترسی به ۵–۱۰ مشتری منتخب بده و اجرای سفارش واقعی را زیر نظر بگیر.
- [ ] پایش روزانه خطای سایت، سبد رهاشده، تماس‌های پشتیبانی و مشکلات پرداخت.
- [ ] رفع سریع ایرادهای UX کشف‌شده (حداکثر ۴۸ ساعت).
- [ ] دریافت جملات واقعی مشتریان برای استفاده در محتوای سایت و کاتالوگ.
- [ ] تنظیم ظرفیت انبار و پشتیبانی بر اساس حجم واقعی سفارش‌ها.

### [ ] راه‌اندازی رسمی و اعلام عمومی  (≈ ۱ هفته · مارکتینگ)
- [ ] کمپین اعلام راه‌اندازی در شبکه‌های اجتماعی، ایمیل و پیامک مشتریان قبلی.
- [ ] ارسال اطلاعیه به فروشندگان/نمایندگان و به‌روزرسانی امضای ایمیل و پروفایل‌های کسب‌وکار.
- [ ] ثبت سایت در ریپازیتوری‌ها و دایرکتوری‌های کسب‌وکار صنعتی.
- [ ] راه‌اندازی کمپین معرفی (تخفیف راه‌اندازی) با هدف جذب اولین سفارش‌ها.
- [ ] صفحه «همکاری و نمایندگی» را فعال و به فروشندگان معرفی کن.

### [ ] آموزش تیم و استقرار SOP  (≈ ۱ هفته · PM/عملیات)
- [ ] راهنمای هر نقش: کارشناس فروش، مسئول انبار، پشتیبانی تلفنی، ادمین سایت، مالی.
- [ ] ویدیوهای کوتاه آموزش پنل (۲–۵ دقیقه) برای هر نقش ضبط کن.
- [ ] فرآیند پشتیبانی و مسیر ارجاع (Escalation) مشتریان را تعریف کن.
- [ ] شیفت‌بندی پاسخ‌دهی تلفن/واتساپ و پاسخ‌گویی خارج از ساعت کاری.
- [ ] بانک پاسخ آماده برای ۳۰ سؤال تکراری مشتریان B2B و B2C بساز.

### [ ] نگهداری، مانیتورینگ و بهبود مستمر  (ماهانه · فنی/مارکتینگ)
- [ ] پشتیبان‌گیری هفتگی و تست بازیابی ماهانه.
- [ ] به‌روزرسانی ماهانه هسته/پلاگین/قالب با تست روی استیج و بکاپ پیش از آن.
- [ ] پایش امنیتی هفتگی و بررسی لاگ‌ها و آسیب‌پذیری‌های اعلام‌شده.
- [ ] بررسی سرعت و Core Web Vitals ماهانه و رفع رگرسیون‌های عملکردی.
- [ ] گزارش ماهانه کسب‌وکار: درآمد، سفارش‌ها، تن فروش، RFQ، نرخ تبدیل کانال‌ها.
- [ ] بک‌لاگ بهبود (Roadmap نسخه بعد): ویژگی‌های درخواستی تیم و مشتریان + اولویت‌بندی.

## پیوست‌ها — ابزارهای پیشنهادی، قالب داده، SOP و مدیریت ریسک  —  ۰٪
> مرجع سریع برای انتخاب ابزار، استانداردسازی داده، آموزش تیم و پیشگیری از ریسک‌های رایج پروژه‌های فروشگاهی صنعتی.

**شرط اتمام فاز:** ابزارها انتخاب و مستند شده، قالب داده نهایی، SOP تیم نوشته‌شده و فهرست ریسک‌ها با اقدام پیشگیرانه تعیین‌شده باشد.

### [ ] استک پیشنهادی و ابزارها (با برآورد نسبی هزینه)  (مرجع · PM/فنی)
- [ ] هاست: VPS با ۲–۴ vCPU و ۴–۸GB RAM + دیسک NVMe، PHP 8.2/8.3، MySQL 8/MariaDB، Redis — هزینه: متوسط (ماهانه).
- [ ] قالب: Woodmart یا Flatsome (بازار فنی خوب، RTL مناسب) یا Blocksy/Kadence برای سبک‌بار بودن — هزینه: متوسط (یک‌بار).
- [ ] پلاگین B2B: B2BKing، Wholesale Suite یا YITH B2B — هزینه: متوسط تا بالا (سالیانه).
- [ ] ایمپورت: WP All Import + افزونه ووکامرس — هزینه: متوسط (سالیانه).
- [ ] سئو: Rank Math Pro یا Yoast — رایگان تا متوسط.
- [ ] کش: LiteSpeed Cache (رایگان) یا WP Rocket — کم تا متوسط.
- [ ] استعلام قیمت: افزونه اختصاصی یا سرویس فرم + CRM — کم تا متوسط.
- [ ] CRM: نوآوران/پیام‌گستر/حلما (سالیانه) یا CRM سبک — متوسط.
- [ ] پیامک و ایمیل: سرویس پیامک ایرانی + SMTP تراکنشی — بر اساس مصرف.
- [ ] درگاه پرداخت: کمیسیون تراکنش (بدون هزینه ثابت معمولاً) — بر اساس فروش.
- [ ] نکته: مجموع هزینه نگهداری سالانه را از ابتدا در برنامه مالی لحاظ کن؛ معمولاً ۱۵–۲۵٪ هزینه ساخت اولیه.

### [ ] قالب استاندارد داده محصول (برای ایمپورت و PIM)  (مرجع · محتوا/فنی)
- [ ] ستون‌های پایه: SKU، نام فارسی، نام انگلیسی، دسته اصلی، دسته فرعی، برند، گرید.
- [ ] ستون‌های مالی: قیمت هر کیلو، قیمت هر واحد بسته‌بندی، MOQ، تخفیف پله‌ای، مالیات، وضعیت موجودی.
- [ ] ستون‌های فنی: MFI/MVR، Density (g/cm³)، Hardness (Shore A/D)، Viscosity (cSt)، Color، Catalyst ratio، Cure Time.
- [ ] ستون‌های کاربردی: Application/صنعت مصرف، جایگزین گرید، شرایط نگهداری، عمر مفید (Shelf life).
- [ ] ستون‌های رسانه: تصویر اصلی، گالری، فایل TDS، فایل MSDS، COA، ویدیو.
- [ ] ستون‌های سئو: Title، Meta Description، Slug، کلمات کلیدی، Alt تصویر.

### [ ] چک‌لیست نهایی انتشار (Release Checklist)  (مرجع · PM)

- [ ] عملکرد: تست سفارش کامل B2C و B2B، پرداخت، ایمیل تأیید، فاکتور، موجودی‌کاهی.
- [ ] امنیت: SSL، بکاپ، فایروال، حذف کاربران تستی و تغییر رمزها.
- [ ] سئو: robots.txt، sitemap، تگ‌های متا، Schema، ریدایرکت‌ها، Search Console.
- [ ] کارایی: امتیاز PageSpeed، تصاویر بهینه، کش فعال و صفحه تسویه مستثنا.

### [ ] SOP فروش و پشتیبانی B2B (متن آماده)  (مرجع · فروش)
